## Findings

### Blockers

None in BE-01. INT-03's blocker (import `IntegrationsModule.forRoot()` in `AppModule`) is BE's to fix but is tracked under INT-03.

### Should fix

1. **Per-IP rate limits will see the proxy, not the patient.** `TRUST_PROXY` defaults to `0`. In production the API sits behind Cloudflare and Render, so every request arrives from a proxy IP. "3 OTP requests per 10 minutes per IP" (BE-04) would then lock out every patient at once.
   - Fix: take the client IP from `CF-Connecting-IP` when the request comes through Cloudflare, or set `TRUST_PROXY` correctly per environment and use `req.ip`. Add a test.
   - INT should put the value in `infra/ENVIRONMENTS.md` (INT-05). Needed before BE-04 is deployed.
2. **5xx logging can carry personal data inside error messages.** `AllExceptionsFilter` logs `exception.stack` for 5xx. Pino redaction works on keys, not on text inside a message string. Mongoose `CastError` and `ValidationError` messages include the offending value, which could be a phone number.
   - Fix: log `name` and `code` plus a stack with the message removed, or scrub E.164 and 6-digit patterns from the message before logging.

### Nits

1. Helmet's default CSP can block Swagger UI's inline scripts in some browsers. The e2e test checks for a 200, not that the UI renders, so open `/api/docs` in a browser once.
2. `x-request-id` is accepted from clients when it matches `^[\w-]{8,64}$`. That is fine, just worth knowing that request ids are client-influenced in logs.
