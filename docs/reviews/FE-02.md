## Findings

### Blockers

1. **The shell is over the 200 KB first-load budget** (FE-02 criterion, TDD 9.1). The biggest movable piece is the full Zod runtime (~34 KB) loaded on every page, because the shell imports shared schemas through the session and API client.
   - Options, in order of payoff:
     - Keep schema parsing out of the shell's first load: dynamic-import the API client or parse lazily, so only pages that call the API load Zod.
     - Load `sonner` on first toast.
     - Ask BE whether `packages/shared` can also export `zod/mini` schemas for the browser.
   - Please also post the measurement method behind the 167 KB figure. If FE's method is the one we should standardise on (it may count differently), RD will adopt it and re-measure.

### Should fix

None.

### Nits

1. The system font stack is fine for now. The Devanagari subset web font is FE-32, as noted.

  These match FE's figures (FE says 172.5 KB for `/login`; the 0.1 KB is rounding). `apps/web/scripts/first-load-js.mjs` gives the same numbers on the same build and exits 0. Largest chunks: react-dom 70.1 KB, Next router 43.0 KB, TanStack Query + sonner 15.4 KB. Headroom is about 24 KB on the heaviest route.
- **Zod is off the first load.** No first-load chunk on any of the five routes contains Zod (searched for `ZodError`, `ZodType`, `_zod`). Zod lives only in a separate chunk (`3op8z6ztb_a75.js` in this build) that loads on the first API call. `src/lib/api/lazy.ts` dynamic-imports `./auth` (and, since this round, the other API modules via a `Proxy` wrapper, `lazy.ts:8-21`). Contract constants come from server pages as props.
- **Measurement method** is now written down and scripted (`apps/web/scripts/first-load-js.mjs`, same method as RD's). RD adopts it as the standard check for later shell changes.
- **Root lint:** `pnpm lint` (eslint, `--max-warnings 0`) exits 0. The round-1 `no-console` error in `first-load-js.mjs` is fixed: the script writes results with `process.stdout.write` (`first-load-js.mjs:25`) and uses only `console.error` (`:30`), which the root config allows (`eslint.config.mjs:50`).
- **Tests:** web Vitest suite, 5 files and 39 tests pass.
- Note: FE was editing `src/lib/api/*` (FE-05 and later stories) during this review. The numbers above are from the 07:15 UTC snapshot. If a later story pulls Zod or a schema into a client component without going through `lazy.ts`, the budget will break again. Run `first-load-js.mjs` in each story that touches the shell or the API client.
