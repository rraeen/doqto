## Findings

### Blockers

None.

### Should fix

1. **The web login exposes the refresh token to JavaScript.** `OtpVerifyResponse` and `RefreshResponse` always return `refreshToken` in the JSON body, and the same call sets the httpOnly `doqto_rt` cookie. Any script running on the web origin can then read a 30-day refresh token from the response, which defeats the point of the httpOnly cookie (TDD 9.2: web uses cookies, mobile uses Bearer).
   - Suggest: return the token pair in the body only when the client asks for it, for example `tokenDelivery: 'body'` in the request or an `X-Doqto-Client: android` header. Web gets cookies only and an `OtpVerifyResponse` without tokens.
   - FE already ignores the body tokens, so this is a contract change BE can make in BE-04 without breaking FE. If BE keeps the current shape, write the reason in `CONTRACT.md`.
2. **`AccessTokenClaims.roles` is `z.array(z.string())`.** It should be `z.array(RoleSchema)` so a guard can never compare against a misspelled role.
3. **Payment gateway enum.** When payments shapes land (BE-24), add `PAYMENT_GATEWAYS = ['razorpay', 'demo']` here. INT-02 already defines `PaymentGateway` locally in `integrations/payment`, and there should be one definition only (differences row 16).

### Nits

1. `ClinicSchema.phone` is an unvalidated string. Clinic landlines are not mobile E.164, so this is fine, but a loose `^\+91\d{6,11}$` would catch typos.
2. `OTP_LOCKED` returns 400. Some teams use 429 for lockouts. Either works, since clients branch on `code`.
