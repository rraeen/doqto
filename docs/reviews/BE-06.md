Focus points:

- **Migration 0002.** `indexMigration` calls `Model.createIndexes()` per model (`migration.ts:11-20`), which only adds missing indexes, and the runner records the name with an upsert (`migration-runner.service.ts:70-74`). It is idempotent and safe after a crash. With `autoIndex` off in production (`database.module.ts:98`) this is the only path that builds them, and probe A shows it does.
- **Audit log schema.** Matches DB doc 3.12 (`actorUserId, action, entity, entityId, before, after, at`) and both indexes. `AuditService.record` takes a session, so a later story can put it in a transaction. The only writer today (BE-09) stores status, `isListed` and notes; no phones, codes or tokens.
- **Slug stability.** The slug follows the primary clinic city until the first listing, then `slugLocked` freezes it (`doctors.service.ts:179-187`). Public URLs (TDD: stable `doqto.in/d/<slug>`) cannot change after a doctor has been listed, even if they are later unlisted and relisted.

## Findings

### Blockers

None.

### Should fix

1. **Two doctors with the same name racing on one slug get a misleading 409 or a 500.** `uniqueSlug` checks `exists` and then the caller saves, so two writers can pick the same free slug. Failure scenarios (from reading the code):
   - Onboarding (`doctors.service.ts:57-80`): two different users named "Rajesh Kumar" onboard at the same moment. Both pick `dr-rajesh-kumar`, the second `create` hits the `slug_1` unique index, and the 11000 catch at line 74 returns **409 "You have already started onboarding"** to a user who has no profile. FE-05 then sends them to "edit profile", which returns 404.
   - `saveWithListing` (`doctors.service.ts:183-188`): two same-name doctors add a clinic in the same city at the same moment. The second `save()` throws 11000 with no catch, so `POST /clinics` or `PATCH /clinics/:id` returns **500** (after the clinic itself was written).
   - The unique index keeps the data correct; only the error is wrong. Fix: when the 11000 `keyPattern` is `slug`, pick the next suffix and retry (a few attempts); map to the "already onboarded" 409 only when `keyPattern` is `userId`. Add a unit test with an `exists` that says "free" and a save that throws 11000 once.
2. **No test proves migration 0002 builds the BE-06 indexes.** e2e runs with `NODE_ENV=test`, so `autoIndex` is on (`database.module.ts:98`) and builds every index at model init. `database.e2e-spec.ts:31-40` drops only the `users` indexes before rerunning migrations, so the doctor and clinic index assertions at `:101-130` pass even if `0002` were missing or listed the wrong models. The `auditLogs` indexes are not asserted at all. Failure scenario: a later edit drops `AuditLog.name` from `0002` (or adds a schema index without a new migration), every test stays green, and production (`autoIndex` off) has no `auditLogs` or new indexes. Fix: in that test, drop the `doctors`, `clinics` and `auditLogs` indexes as well, and assert each DB doc index after `runPending()` (probe A is a ready template).

### Nits

1. `indexMigration` reads the model's **current** schema when it runs (`migration.ts:17`), so `0002` is not a snapshot. That is fine, but a new index on `Doctor` or `Clinic` reaches databases that already applied `0002` only through a new migration naming the model again. Say so in the header of `migrations/index.ts:29-32`.
2. The comment on `verification.submittedAt` (`doctor.schema.ts:40`) says it orders the admin queue, but the queue sorts and pages on `createdAt` (`admin-doctors.service.ts:65-82`), which is what the `{verification.status, createdAt}` index serves. Fix the comment (or the BE-09 query, with a matching index).
3. `auditLogs` has no retention. DB doc 6 says 24 months. A TTL index on `at` (`expireAfterSeconds` of about 730 days) in a later migration, or a note for BE-42, would close it.
4. `consultFee` and `bookingFee` have no schema `min`/`max` or integer check (`doctor.schema.ts:79-81`). Only the DTO enforces paise 1000 to 2000. The seed and later writers bypass DTOs.
5. Names with no Latin letters all become `dr-doctor-<city>` (`slug.ts:11`, spec case `डॉ शर्मा`). That works, but the URL loses the name for SEO (FE-08). Transliteration can come later.
