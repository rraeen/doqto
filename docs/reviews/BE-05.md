Focus points:

- **Strict allowlist.** `UpdateDoctorProfileRequestSchema` (`doctors.ts:91-105`) is `.strict()` and lists only editable fields. The test at `contract-v1.spec.ts:41-43` rejects `ratingSummary`, `verification`, `isListed` and `slug`. The API applies the patch field by field (`apps/api/src/doctors/doctors.service.ts:104-125`).
- **Fees.** `bookingFee` is integer paise from 1000 to 2000 (`doctors.ts:20-21,58`), which matches DB doc 3.2. `consultFee` is integer paise from 0 to ₹10,000 (`:23,57`). The test rejects `500` and `15.5`.
- **ADR 0008.** No payment, plan or fee field feeds ranking. `DoctorSearchQuery` has no such parameter. `consultFee` in `DoctorListItem` is display-only output. The ranking input type (`apps/api/src/ranking/rank-doctors.ts:6-17`) has distance, specialty, availability, score and review count only.
- **PII.** No public type carries a user phone. `ClinicSchema.phone` is the clinic's own number. Doctor phones appear only in the admin shapes (`admin.ts:16,29`), which are admin-only. See Should fix 3 for staff phones.
- **No clinical data (ADR 0007).** None. `bio` is free text written by the doctor, not about patients.
- **SpecialtyKey breaking change.** `DoctorListItem` and `DoctorProfile` specialties are now `SpecialtyKey`s. `apps/web/src/mocks/handlers.ts` has no doctor mocks yet, so nothing breaks today. FE-08 and FE-09 mocks must use keys such as `general_physician` and show `SPECIALTIES[].en` / `.hi`, never the key.
- **CONTRACT.md** matches the schemas and routes, with one gap (Should fix 2).

## Findings

### Blockers

None.

### Should fix

1. **`near` has no India bounds, so an out-of-range value returns 500.** The regex at `packages/shared/src/doctors.ts:199-202` accepts any 1-2 digit latitude and 1-3 digit longitude. `CONTRACT.md:118` says request coordinates use India bounds, but that applies only to `LatLngSchema`. Failure scenario: a public, unauthenticated `GET /api/v1/doctors?near=95,200` reaches `$geoNear` and returns `500 INTERNAL` (RD probe). This duplicates BE-10 Should fix 2, which covers the API side.
   - Fix: in a `superRefine`, parse `near` and check it against `LatLngSchema`, then mirror the check in `apps/api/src/doctors/dto/search.dto.ts:37`. One fix closes both reviews.
2. **CONTRACT.md misses one error.** `POST /admin/doctors/:id/verify` returns `409 CONFLICT` when approving a doctor who has not uploaded a registration document (`apps/api/src/admin/admin-doctors.service.ts:143-148`). `CONTRACT.md:112` lists only `NOT_FOUND`. Failure scenario: FE-07 has no copy for this case and shows a generic error. Add `CONFLICT` (no document uploaded) to the row.
3. **Read-only staff receive every co-worker's phone.** `ClinicPrivateSchema.staff[].phone` (`clinics.ts:39-51`) is returned to anyone with clinic access, including `staff` (read-only) access (`apps/api/src/clinics/clinics.service.ts:40-54`, `canManage: false`). Failure scenario: a front-desk user calls `GET /clinics/:id` and gets the mobile numbers of all other staff at the clinic.
   - I do not rate this a checklist E "never" breach. The data is not patient data, it goes only to people the clinic owner added, and the owner entered those numbers. It is still more than a read-only role needs (DPDP data minimisation).
   - Fix: return `staff: []` (or names only) when `canManage` is false, and say so in the schema comment.

### Nits

1. `AdminDoctorQueueItemSchema.specialties` is `z.array(z.string())` (`admin.ts:18`). Use `SpecialtyKeySchema` like the other doctor shapes, so FE-07 gets typed keys to label.
2. `packages/shared/package.json:3` still says `"version": "0.1.0"`, but `CONTRACT_VERSION` and `CONTRACT.md` say 1.0.0. Bump it, or note that `CONTRACT_VERSION` is the only version that counts.
3. `languages` is free text (`doctors.ts:53`). A small controlled list (as with specialties) would make the Hindi labels and any future filter easier. This can wait.
