## Acceptance criteria

| Criterion | Holds? | Evidence |
| --- | --- | --- |
| Mongoose connection from `MONGODB_URI`; `autoIndex` off in production; startup migration runner applies indexes idempotently and records them in `migrations` | Yes | `database.module.ts` (`autoIndex: !isProduction`, `dbName` from `MONGODB_DB_NAME`). `MigrationRunner.onApplicationBootstrap` upserts by name. e2e "records applied migrations and is idempotent" and "creates indexes from migrations even with autoIndex off" |
| `users`, `otps` (TTL on `expiresAt`), `refreshTokens` (unique `tokenHash`, TTL) per DB doc 3.1 and 3.12; `isDemo` on users | Yes | Schemas match DB doc field names (`deviceHashes`, `consentLog`, `pushSubscriptions`, `clinicIds`, status with `deleted`). The unique `phone` index has a duplicate-insert test expecting 11000 (`database.e2e-spec.ts:45`). Both TTL indexes are asserted |
| Tests use `mongodb-memory-server` in replica-set mode | Yes | `test/global-setup.ts`. Each e2e file gets its own `doqto_demo_test_*` database |

Deviations, accepted and recorded:

- `otps { phone, purpose }` is **unique**, where the DB doc has a plain index. This is better: one live code per phone and purpose, even with concurrent requests.
- `refreshTokens.familyId` (indexed) supports reuse detection in BE-04.
- `consentLog[].granted` records withdrawals as well as grants.

I've added these three to `docs/reviews/design-doc-differences.md`.

## Findings

### Blockers

None.

### Should fix

1. **Duplicate-insert tests for the other two unique indexes.** Checklist F asks for an 11000 test on each release-blocking unique index. Only `users.phone` has one.
   - Add the same one-line test for `refreshTokens.tokenHash` and for `otps { phone, purpose }`. The current tests check that those indexes exist, but not that they reject a duplicate.

### Nits

1. `mongodb-memory-server` is pinned to 8.0.14, which has no Ubuntu 24.04 build on fastdl. Locally this only matters on Ubuntu 24.04 without `MONGOMS_SYSTEM_BINARY`. Pinning `8.0.x` to a version with a 2404 build, or setting `MONGOMS_DISTRO=ubuntu-22.04`, makes the first run smoother.
2. `pushSubscriptions[].endpoint` is stored in clear text, as the DB doc says. That is fine for Web Push. BE-42 account deletion must remove it.
