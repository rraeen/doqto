# Doqto UI audit: mobile type, spacing and alignment

**Date:** 2026-10-20 · **Build:** local dev (`http://192.168.1.19:3000`, demo mode) · **Scope:** report only, no code changed

## How this was checked

- Headless Chrome (Playwright) at **360×780**, **390×844** (both 2× DPR, touch) and **1440×900**.
- Three sessions: signed out, demo patient (`+91 90000 00099`), demo doctor (`+91 90000 00011`, Dr Anita Sharma).
- For every page a script also recorded the font sizes and weights in use, any text under 13px, tap targets under 44px, and elements that run past the viewport edge. Raw numbers are in [`screenshots/metrics.json`](screenshots/metrics.json).
- Screenshots: `screenshots/<page>-<360|390|desktop>.png` (full page) and `<page>-<360|390>-fold.png` (first screen only).
- **Not covered:** admin pages (the admin phone is not in the repo, so `/admin/*` showed "Only Doqto admins can open this page"), detail pages that need an ID (`/consult/[id]`, prescription, `/clinic/clinics/[id]`), and the OTP step.
- **Ignore** the round black "N" button in the screenshots. It is the Next.js dev indicator and does not ship. In full-page shots the floating bottom nav appears mid-page because Playwright stitches the page; on a real phone it sits at the bottom.

## 1. Global fixes (do these first, they fix most pages at once)

### 1.1 Type scale

**Problem.** The theme in `apps/web/src/app/globals.css` overrides `xs` to `3xl` but not `4xl`, so `text-4xl` falls back to Tailwind's default of 2.25rem, the **same 36px as `text-3xl`**. Every `text-3xl … sm:text-4xl` page title (Appointments, Book a visit, Consult, Help, Profile, Edit profile, Records) never changes size. Meanwhile `PageTitle` in `components/shell/page.tsx` uses `text-2xl sm:text-3xl` (28 → 36px) and the patient home uses `text-[20px]`. So, at 390px:

| Page | h1 size at 390 | h1 size at 1440 |
|---|---|---|
| Patient home "Welcome to Doqto" | **20px** | 28px |
| Search, Doctor profile, Clinic pages, Login | 28px | 36px (doctor profile stays 28px) |
| Appointments, Book a visit, Consult, Records, Profile, Help | **36px** black | 36px |
| Install | 36px | 48px |
| Landing hero | 48px | 72px |

Other things the metrics found: 11px text in 9 places (`text-[11px]`), a one-off `text-[13px]` in `navs.tsx`, and seven weights in use (400, 500, 600, 700, 800, 900).

**Fix.** Define one scale with line heights, and add a `2xs` step so nothing needs an arbitrary size:

```css
@theme {
  --text-2xs: 0.75rem;   --text-2xs--line-height: 1rem;      /* 12 / 16  badges, nav labels only */
  --text-xs: 0.8125rem;  --text-xs--line-height: 1.125rem;   /* 13 / 18  meta, captions */
  --text-sm: 0.9375rem;  --text-sm--line-height: 1.375rem;   /* 15 / 22  secondary body */
  --text-base: 1rem;     --text-base--line-height: 1.5rem;   /* 16 / 24  body, inputs */
  --text-lg: 1.125rem;   --text-lg--line-height: 1.625rem;   /* 18 / 26  section titles */
  --text-xl: 1.25rem;    --text-xl--line-height: 1.75rem;    /* 20 / 28 */
  --text-2xl: 1.5rem;    --text-2xl--line-height: 2rem;      /* 24 / 32  mobile page title */
  --text-3xl: 1.875rem;  --text-3xl--line-height: 2.25rem;   /* 30 / 36  desktop page title */
  --text-4xl: 2.25rem;   --text-4xl--line-height: 2.5rem;    /* 36 / 40  mobile hero */
  --text-5xl: 3rem;      --text-5xl--line-height: 3.25rem;   /* 48 / 52 */
  --text-6xl: 3.75rem;   --text-6xl--line-height: 4rem;      /* 60 / 64  desktop hero */
}
```

Then use roles, not sizes, everywhere:

| Role | Mobile | ≥ md | Weight |
|---|---|---|---|
| Page title (h1, in-app) | `text-2xl` 24px | `md:text-3xl` 30px | `font-bold tracking-tight` |
| Section title (h2) | `text-lg` 18px | `md:text-xl` 20px | `font-semibold` |
| Card title | `text-base` 16px | same | `font-semibold` |
| Body | `text-base` 16px | same | `font-normal` |
| Secondary / meta | `text-sm` 15px or `text-xs` 13px | same | `font-normal text-ink-muted` |
| Eyebrow / overline | `text-xs` 13px | same | `font-semibold uppercase tracking-wide` (use sparingly) |
| Badge, nav label | `text-2xs` 12px minimum | `text-xs` | `font-semibold` |
| Marketing hero | `text-4xl` 36px | `sm:text-5xl lg:text-6xl` | `font-extrabold` |

Make every h1 go through `PageTitle` (`text-2xl md:text-3xl font-bold tracking-tight text-ink`) and delete the per-page `text-3xl font-black … sm:text-4xl` strings. Replace all `text-[11px]` with `text-2xs` and `text-[20px]` with `PageTitle`. **P1.**

### 1.2 Weights

**Problem.** `font-black` (900) appears 27 times and `font-extrabold` is common for labels, pills and nav. Combined with the neumorphic shadows the app reads heavy and a bit toy-like rather than clinical.

**Fix.** Allow only 400, 500, 600, 700, plus 800 for the landing hero. Headings `font-bold`, buttons and labels `font-semibold`, nav labels `font-semibold` (not `font-extrabold`). **P1.**

### 1.3 Page gutters and vertical rhythm

**Problem.** Mobile content mostly sits at 16px from the edge, but cards then use 16, 20 or 24px inner padding depending on the page, and section gaps range from 12px to 64px (e.g. the patient home "Reminders" block sits closer to "Quick actions" than "Why Doqto" does). On the landing page the gaps between sections at 390px are very large, and the page is about 5,000px tall.

**Fix.**
- Page shell: `px-4 sm:px-6 lg:px-8`, `max-w-screen-lg mx-auto` for app pages.
- Between sections: `space-y-8` (32px) on mobile, `md:space-y-10`.
- Section title to its content: `mb-3`.
- Cards: `p-4` mobile, `md:p-5`; list cards `gap-3`.
- Landing sections: `py-12 sm:py-16 lg:py-24` instead of the current fixed large padding.
- Content above the floating bottom nav: `pb-[calc(6rem+env(safe-area-inset-bottom))] md:pb-8`. **P1.**

### 1.4 Header at 360px (G1) — **P0**

**Problem.** At 360px the header row is wider than the screen: `scrollWidth` 364 on the landing, For doctors and Install pages (the ☰ menu button is cut off), and 361 on every clinic page (the avatar is cut off). On clinic pages the "Clinic console" pill wraps to two lines. See `home-360-fold.png`, `install-360.png`, `clinic-dashboard-360-fold.png`.

**Fix** (`components/shell/app-header.tsx`):
- Give the grid `grid-cols-[auto_minmax(0,1fr)_auto]` and the right cluster `min-w-0 gap-1.5 sm:gap-3`.
- Under 380px move the EN/हि switch into the menu sheet: `hidden min-[380px]:flex`.
- Landing "Login" button: `h-10 px-3 text-sm` on mobile.
- Clinic badge: `whitespace-nowrap text-2xs px-2 py-0.5`, and `hidden min-[380px]:inline-flex` (the bottom nav already tells the user they are in the console).
- Logo wordmark `text-xl` on mobile instead of the current size.

### 1.5 Disabled buttons (G3) — **P0**

**Problem.** Disabled primary buttons use `disabled:opacity-50` on the bright green fill, so the label becomes grey on pale green, well below 3:1. Seen on "Online booking is coming soon" (doctor profile), "Review and confirm" (Book a visit) and "Save changes" (clinic profile). People will think the page is broken.

**Fix** (`components/ui/button.tsx`): replace `disabled:opacity-50` with `disabled:bg-line disabled:text-ink-muted disabled:shadow-none`. For "coming soon" states, don't use a button at all; show a neutral note (`rounded-xl bg-surface p-4 text-sm text-ink-muted`).

### 1.6 Class merging in `buttonVariants` (G7) — **P1**

**Problem.** `buttonVariants({ variant: 'outline', className: 'h-20 flex-col' })` is plain `cva`, which concatenates classes without `twMerge`. The `md` size adds `h-tap`, which wins over `h-20`, so the clinic home tiles render 44px tall with the icon squeezed to ~12px above the label (`clinic-dashboard-desktop.png`). Separately, `twMerge` does not know the custom `tap` spacing or the new `2xs` size, so even `cn()` won't resolve those conflicts.

**Fix.** Use `cn(buttonVariants({ variant: 'outline' }), 'h-20 flex-col')`, or wrap `buttonVariants` once so it always runs through `cn`. In `lib/cn.ts` switch to `extendTailwindMerge({ extend: { theme: { spacing: ['tap', 'tap-lg'], text: ['2xs'] } } })`.

### 1.7 Tap targets (G8) — **P1**

Measured under 44px on mobile:

| Control | Size | Fix |
|---|---|---|
| EN / हि switch | 40×32, 36×32 | `h-tap min-w-tap` per segment |
| Directions / Call (doctor profile) | 122×36, 75×36 | `size="md"` (h-tap) |
| Filter chips (Records, Consult, Admin) | ~37px tall | `h-10` is acceptable for chips if spaced `gap-2`; preferred `min-h-tap` |
| Calendar prev/next | 36×36 | `size-tap` |
| Footer links, "Find a doctor" etc. | 21px tall | `inline-flex min-h-tap items-center px-2` |
| "View profile" (booking) | 132×29 | `h-9` minimum, `text-xs font-semibold` |
| Profile edit language toggles | 32px | `h-tap` |

### 1.8 Colour (G10, G11) — **P2**

- **Off-brand blue:** "New on Doqto" badge, "Admin" pill, the blue left border on "Delay alerts" and the "On WhatsApp" link. Use `bg-brand-50 text-brand-700 ring-brand-200` for positive badges and keep `info` blue only for genuinely informational notices.
- **Neon fills:** `brand-500` (#13ec13) as a full-width button fill with glow looks promotional. For a more clinical, commercial look consider `bg-brand-600 text-white` for primary buttons, keep `brand-500` for small accents (dots, active states), and drop the green glow shadow on buttons. This is a brand call, so it's P2.

## 3. PWA notes

- Manifest, maskable icon, `viewport-fit=cover`, `theme-color` and Apple touch icon are all present. Good.
- The bottom nav already uses `pb-safe`; keep one shared bottom padding on every signed-in page (see 1.3) so the last card always clears the floating nav.
- `theme-color` is the same grey-green as the canvas, so the status bar blends in. That's fine; if primary buttons move to `brand-600`, consider no change here.

## 4. Suggested order

1. P0 fixes: header at 360, sticky save bar, disabled buttons, clinic card overflow.
2. Type scale tokens + `PageTitle` everywhere + remove `text-[11px]` (one PR, touches many files but is mechanical).
3. `buttonVariants`/`cn` merge fix and tap-target sizes.
4. Page-level layout tweaks (Records stats, Consult/Records chips, Book a visit cards, Profile).
5. P2 colour and polish.
